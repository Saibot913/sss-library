# Changelog

All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/); versioning follows [Semantic Versioning](https://semver.org/) (`MAJOR.MINOR.PATCH`, tracked in `package.json`):

- **MAJOR** — breaking change (something that worked before no longer does).
- **MINOR** — new feature, backwards compatible.
- **PATCH** — bug fix, no new feature.
- Version stays under `0.x.x` until there's a real, working first release — see [semver.org, point 4](https://semver.org/#spec-item-4).

## How to use this file

Every PR adds a line under `[Unreleased]`, in the right section (`Added` / `Changed` / `Fixed` / `Removed`). This is required, not optional: `.github/workflows/changelog.yml` fails any PR into `main` that doesn't touch this file — but the entry itself doesn't need to be a full writeup. A short, plain-language line is enough for most changes ("Fixed catalog sort order"); only add more detail when the *why* isn't obvious from the line alone (a non-obvious tradeoff, a workaround, something a reader would otherwise wonder about). Use judgment — terse by default.

When a set of changes is ready to be called a release: bump `version` in `package.json` following the rules above, rename `[Unreleased]` below to the new version number + today's date, and start a fresh empty `[Unreleased]` section above it.

## [Unreleased]

### Removed
- The "top 4 categories" pill row under the homepage search box — cluttered and redundant with the catalog's own category filter.

### Fixed
- Clicking "Settings" or "My Books" in the top nav while viewing a book's detail page did nothing — those buttons navigate to a real route, but the detail overlay only checks its own `viewingBook` state to decide what to render, so it kept covering the page underneath. Both handlers now clear `viewingBook` before navigating, matching what the main nav links (Home/Catalog/etc.) already did.
- Top-right nav "My Books" button had less horizontal padding than the adjacent "Settings"/"Cart" buttons, making it visibly narrower — matched its padding to the other two.
- Thought for the Day text showed raw HTML entities (e.g. `&ldquo;`, `&rsquo;`) instead of curly quotes/dashes — the Apps Script importer's `decodeEntities()` only handled a handful of entities and missed the ones the Sai Inspires email actually uses. Only fixes rows imported from now on; existing rows in `thought_of_the_day` still have the raw entities baked in.
- Clicking "Check Out" did nothing when the signed-in patron didn't have a complete profile (or wasn't signed in at all) — `ProfilePage`/`LoginModal` were shown, but the cart drawer (a full-screen fixed overlay) was left open on top of them, rendering the form invisible behind it. Both paths now close the cart first.
- The incomplete-profile prompt at checkout rendered in normal document flow instead of as an overlay, so it could land off-screen below the fold (or at the bottom of the page) depending on scroll position — looked identical to checkout silently doing nothing. It's now a dismissible fixed-overlay modal, so patrons can close it and keep browsing without completing their profile; checkout just stays blocked until they do. Confirmed working end-to-end after this change.
- The top nav's active-tab highlight defaulted to "Home" for any route not in the 5 main tabs (e.g. `/account`), so Home stayed lit up while viewing Profile/Settings pages.
- `staff_list_checkouts()` 400'd on every call since it was introduced in migration `0018` — it declared `checked_out_at` as `timestamptz` but the column is a plain `timestamp`, and Postgres's stricter type-checking for `RETURN QUERY` in PL/pgSQL functions rejected the mismatch outright. The Returns & Holds staff page could never load open checkouts as a result (migration `0021`). Its `patron_name` was also missing the space between first and last name (migration `0022`).
- Site-wide sweep of tiny text: any inline `fontSize` under 12px (mono section eyebrows, book-detail "Publication Details"/"Keywords" labels, catalog availability counts, nav numerals, etc.) was raised to at least 12px, with a few directly-adjacent sizes nudged up too so the hierarchy still reads cleanly rather than everything collapsing to one size.
- 12px still read as too small once seen in place (section eyebrows, body paragraphs on the Community page, book-detail labels) — raised the floor from the previous pass to 14px across the board. Left the 18px circular cart-count badge at 12px since 14px would start clipping double-digit counts.
- "Mark Returned" on the staff Returns & Holds page has never worked — `staff_return_book()` declares `RETURNS TABLE(checkout_id uuid, full_label text, returned_at timestamptz)`, and in PL/pgSQL every `RETURNS TABLE` column name becomes an implicit variable in scope for the whole function body. Its two `UPDATE` statements referenced bare `full_label` in their `WHERE` clauses, which Postgres couldn't resolve between that implicit output variable and the actual `checkouts.full_label`/`copies.full_label` table columns — every call failed with `42702 column reference "full_label" is ambiguous`. Fixed by qualifying the table references explicitly (migration `0025`).
- Catalog card grid divider lines rendered inconsistently between rows — the grid used a 1px `gap` over a solid background color to fake borders, which subpixel-rounds away on some rows depending on card width. Replaced with explicit `border-right`/`border-bottom` on each card so the lines always show.
- Book covers that hit a transient failure (a `429` rate limit or `5xx` from Google Books/Open Library, e.g. during a fast scroll through the catalog) got cached in `localStorage` as "no cover" exactly like a confirmed empty result — permanently marking that book coverless even though a retry moments later would have worked. Transient failures now propagate without writing a negative cache entry, so the next page load retries them instead of being stuck. Existing browsers that already hit this before the fix still have those false negatives cached — clearing `localStorage` (or just the `bookCover:` prefixed keys) picks them back up.

### Added
- A patron's cart now updates live when staff force-release their hold from the Returns & Holds page — previously the patron's own browser had no way to find out (cart is pure client-side state with no server sync), so it kept showing a book they no longer actually had reserved until they tried checkout (which then correctly failed) or reloaded. Uses Supabase Realtime "Broadcast from Database" on a private, per-patron channel (migration `0026`) rather than a plain `postgres_changes` subscription on `copies` — deliberately avoids relying on Realtime respecting the column-level `REVOKE` on `reserved_by`/`reserved_until` (added in migration `0001` specifically so patrons can't see who else has what on hold), which is genuinely unclear from Supabase's docs. The broadcast payload only ever contains the released book's label, and Realtime Authorization (an RLS policy on `realtime.messages`, scoped by `realtime.topic()` against `auth.uid()`) means a patron can only subscribe to their own channel.
- Wired up the Community page's Volunteer and Reviews & Feedback sections to the real Google Forms — `VOLUNTEER_FORM_URL`/`REVIEW_FORM_URL` are now set, so visitors get an "Open Form ↗" button that hands off to Google Forms (which drops responses straight into a linked Sheet) instead of the old "coming soon" placeholder.
- New staff Volunteers page (`/staff/volunteers`, added to the Staff hub) linking to the volunteer response spreadsheet, so staff can follow up with interested volunteers. Currently just the link plus a "more to come" note.
- Staff Reviews page now links directly to the Reviews & Feedback response spreadsheet at the top, instead of just mentioning it needs to be checked.
- Waitlist feature: a "Join Waitlist" button on the book detail page, shown once a book has zero available copies (`waitlist` table + `join_waitlist`/`leave_waitlist`/`is_on_waitlist` RPCs, migration `0024_waitlist.sql`). Reuses the signed-in patron's existing profile (name/phone/email) rather than a new form — same login/complete-profile gating as adding to cart. `join_waitlist` reads that profile server-side rather than trusting client-supplied values, following the reserve_copy/checkout_book security-definer pattern.
- Book cover art (`src/lib/bookCovers.ts`), enabled everywhere a `BookCover` renders — catalog grid, cart, detail page hero, recommendations, home page — not just the detail page. Two sources tried in order: Google Books API (requires `VITE_GOOGLE_BOOKS_API_KEY` in `.env` — anonymous/keyless requests return `429`/quota-exhausted unconditionally, confirmed against the live endpoint), then Open Library's free/keyless covers API as a fallback for titles Google doesn't have. Neither source indexes most of this catalog's niche religious-publication titles, so the 📖 placeholder is still the common case. Fetches are gated by `IntersectionObserver` (only fire once a card scrolls into view, so a 100+ book grid doesn't fire every request on page load) and deduped by an in-flight-request map (without which React StrictMode's mount→cleanup→mount in dev, or the same book rendered in two places at once, each fire their own real network request). Cached in-memory + localStorage per title/author so a book is only ever fetched once per browser.
- Per-book and library reviews, staff-curated (`reviews` table, migration `0019_book_reviews.sql`; `add_review`/`delete_review` RPCs; new `/staff/reviews` page). One table for both: a review with a `book_code` shows up on that book's detail page under "Reader Reviews"; one without shows up in the Community tab under "§ 04 What People Are Saying" (most recent 15, horizontally scrollable — not an auto-advancing carousel, so a visitor reads at their own pace). Source is still the external Reviews & Feedback Google Form — staff reads the spreadsheet and types in the ones worth publishing; decided against a Google Sheets API integration for this to avoid new external credentials, revisit if manual entry becomes a bottleneck. Form setup instructions (`src/lib/reviews.ts`) updated to describe a Category dropdown (Book Review / Library Review) with Forms' branching so a Book Title field only shows for Book Review.
- Staff "Manage Books" page (`/staff/books`, in the account menu) — combines Add and Edit into one page (Add on top, Edit below) rather than two separate nav items. Add has two modes: "add a copy of an existing book" (search by title, pick it, just enter a location — inserts one `copies` row) and "add a brand new book" (full form, live-suggests a `book_code` and steers toward "add a copy" instead if a similar title already exists). Edit lets staff change every book field except `title`, plus each copy's `location`/`status` — a `checked_out` copy can't be edited here, matching the existing "process a return first" rule enforced server-side by `update_copy`. Pure UI on the already-existing `add_book`/`add_copy`/`update_book`/`update_copy` RPCs (`0015`) — no new migration.

- Real URLs for each page via `react-router-dom` (`/`, `/catalog`, `/thought`, `/community`), replacing the state-based view switching — pages can now be linked to, bookmarked and refreshed, and the back button moves between them instead of leaving the site. Unknown paths redirect home, and scroll resets on navigation. Two things to know: book detail is still component state so individual books have no URL yet, and `BrowserRouter` needs the host to serve `index.html` for unknown paths (Vercel/Netlify do this for Vite SPAs by default; a plain static server will 404 when someone refreshes `/catalog`).

- Checkout actually works. The cart's button says "Check Out N Books" instead of "Submit Hold Requests" and calls `checkoutBookByCode()`, which asks the database for an available copy at the moment of checkout rather than trusting the cached catalog — the cache carries no copy labels, and a copy held in someone else's cart still reads as available because the hold lives in `reserved_until`, which column grants hide from the client. Several candidates are fetched so a copy lost to someone else mid-checkout becomes a retry rather than an error. Afterwards the cache is invalidated and the catalog refetched, and partial failures are reported by title with only those books left in the cart.
- One-time patron details form, shown before a first checkout: name and phone, validated (accepts `(916) 805-0152`, `916.805.0152`, `+1 916 805 0152`; rejects anything that isn't a plausible US number) and normalised to one format. Stored in the auth user's `user_metadata` rather than a `patrons` table, which still doesn't exist — fine for someone's own contact details, but note the same field is deliberately *not* used for staff membership, since users can write their own metadata. The saved name replaces the email local-part in the top-right button.
- Account menu in the top right. Clicking your name used to sign you out on the spot; it now opens a menu showing which account you're signed in as, with an explicit Sign Out. Closes on outside click or Escape.

### Changed

The library has neither Fiction nor Non-Fiction, so picking either filtered every book out — the dropdown was worse than useless. - Thought for the Day shows the short quote *after* the discourse rather than before it, matching the order of the email it comes from.
- Contact footer uses the real centre name, address and room from `siteInfo.ts`, replacing '418 Elm Street' / '(614) 555-0187' / 'hello@sailibrary.org'. The Phone and Email columns are gone rather than filled in: no public number or address exists in the project, and an invented one on a real site is worse than none.
- `auth.ts` stubs reshaped around the email + one-time-code flow: `requestSignInCode()` and `verifySignInCode()` replace `signIn(cardId, name)`, since a code flow is inherently two steps, and `onAuthChange()` is added so the UI tracks token refresh and cross-tab sign-out. `cardId` is gone from `Patron`. - The task list now specifies email + one-time-code authentication, and drops library cards. Cards were Figma mockup leftovers — no card number exists anywhere in the database, and one couldn't serve as a credential regardless since it's printed on the card. Adds open decisions for who may sign up and who runs the mail sender.

### Fixed
- The thought-of-the-day importer's setup docs said to use a new-style `sb_secret_` key, which cannot work: Supabase rejects secret keys when the `User-Agent` looks like a browser, Apps Script's starts with `Mozilla/5.0`, and Apps Script strips any `User-Agent` you set. It now says to use the legacy `service_role` JWT, and notes that legacy keys retire at the end of 2026 along with the two ways out (an Edge Function in front, or moving the job to GitHub Actions over IMAP).
